# 🧹 Garbage Collection في JavaScript – شرح مفصل

## 1. الذاكرة إيه وليه مهمة؟

لما بتكتب كود JavaScript، كل حاجة بتعملها بتاخد مساحة في الـ RAM (ذاكرة الجهاز):

```javascript
let name = "Ahmed";           // مساحة للـ string
let age = 25;                 // مساحة للـ number
let user = { name: "Ahmed" }; // مساحة للـ object
```

الـ RAM مش لانهائية. لو كل حاجة بتعملها فضلت في الذاكرة للأبد، البرنامج هيبطأ وفي الآخر هينهار.

السؤال: **مين المسؤول عن تنضيف الذاكرة؟**

في لغات زي C، إنت اللي مسؤول يدويًا. في JavaScript، فيه نظام تلقائي بيعمل ده اسمه **Garbage Collector**.

---

## 2. الفكرة الأساسية: Reachability (قابلية الوصول)

الـ Garbage Collector بيشتغل على فكرة واحدة بس:

> **أي كائن تقدر توصله = يفضل في الذاكرة.**
> **أي كائن ملقتش طريق توصله = زبالة وبيتشال.**

### إزاي بيحدد "تقدر توصله"؟

بيبدأ من حاجات اسمها **Roots** (الجذور). الـ Roots دي النقاط الثابتة اللي JavaScript دايمًا عارفاها:

```javascript
// 1. المتغيرات العامة = Roots دايمًا
let user = { name: "Ahmed" };

// 2. الدالة اللي شغالة حاليًا ومتغيراتها = Roots
function greet() {
  let message = "Hello"; // Root طول ما الدالة شغالة
}
```

أي كائن الـ Roots بتشاور عليه = Reachable = يفضل.
أي كائن محدش بيشاور عليه من الـ Roots = Unreachable = يتشال.

---

## 3. مثال بسيط: مرجع واحد

```javascript
let user = { name: "John" };
```

دلوقتي في الذاكرة:
- المتغير `user` (جذر) بيشاور على الكائن `{ name: "John" }`
- الكائن **Reachable** ← يفضل في الذاكرة ✅

```javascript
user = null;
```

دلوقتي:
- `user` بقى `null`، يعني مش بيشاور على الكائن
- الكائن `{ name: "John" }` مفيش حاجة بتشاور عليه
- الكائن **Unreachable** ← الـ Garbage Collector هيشيله ❌

---

## 4. مثال: مرجعين

```javascript
let user = { name: "John" };
let admin = user; // admin بيشاور على نفس الكائن
```

دلوقتي الكائن `{ name: "John" }` عنده **مرجعين** بيشاوروا عليه:
- `user` (جذر)
- `admin` (جذر)

```javascript
user = null; // قطعنا مرجع واحد بس
```

الكائن لسه **Reachable** عن طريق `admin`. مش هيتشال.

```javascript
admin = null; // قطعنا المرجع التاني
```

دلوقتي مفيش حاجة بتشاور على الكائن. **Unreachable** ← هيتشال.

---

## 5. مثال متقدم: الكائنات المترابطة

```javascript
function marry(man, woman) {
  woman.husband = man;  // آن بتشاور على جون
  man.wife = woman;     // جون بيشاور على آن

  return {
    father: man,        // كائن العيلة بيشاور على جون
    mother: woman       // كائن العيلة بيشاور على آن
  };
}

let family = marry({ name: "John" }, { name: "Ann" });
```

**الذاكرة دلوقتي:**

```
family (جذر)
  ├── father → { name: "John", wife: → Ann }
  └── mother → { name: "Ann", husband: → John }
```

كل الكائنات Reachable عن طريق `family`. كلهم عايشين ✅

---

### لو حذفنا مرجعين:

```javascript
delete family.father;          // مسحنا المرجع لجون من family
delete family.mother.husband;  // مسحنا المرجع لجون من آن
```

**الذاكرة بقت:**

```
family (جذر)
  └── mother → { name: "Ann" }  ✅ عايشة

{ name: "John" } ← مفيش حاجة بتشاور عليه من الجذور ❌
```

> **ملاحظة مهمة:** جون لسه بيشاور على آن (عنده `wife`)، بس ده مش مهم. المهم **مين بيشاور على جون** من الجذور. ومفيش حد. فجون هيتشال.

---

## 6. الجزيرة المنعزلة (Unreachable Island)

```javascript
family = null;
```

دلوقتي كائن العيلة نفسه بقى Unreachable. حتى لو جون وآن جواه بيشاوروا على بعض، مفيش طريق من أي جذر ليهم.

**الجزيرة كلها هتتشال:** كائن العيلة + جون + آن.

> جون وآن ممكن يبقوا مرتبطين بالمراجع جوه بعض، بس لو انقطعوا عن الجذور، مفيش فايدة. الكل بيتشال.

---

## 7. الخوارزمية: Mark-and-Sweep

الـ Garbage Collector بيشتغل بالطريقة دي:

**الخطوة 1 – Mark (تعليم):**
يبدأ من كل الـ Roots ويعلم كل كائن يوصله.

**الخطوة 2 – Visit (زيارة):**
يزور الكائنات المتعلمة ويعلم اللي بيشاوروا عليه.

**الخطوة 3 – Repeat (تكرار):**
يكرر لحد ما يزور كل حاجة Reachable.

**الخطوة 4 – Sweep (كنس):**
أي كائن متعلمش = Unreachable = يتشال.

```
Roots → A → B → C  (كلهم اتعلموا ✅)
      → D           (اتعلم ✅)

E → F  (محدش وصلهم من الـ Roots ❌ هيتشالوا)
```

---

## 8. تحسينات المحركات

المحركات الحديثة زي V8 (اللي بيشغل Chrome و Node.js) بتستخدم تحسينات عشان الـ Garbage Collection ميأثرش على أداء البرنامج:

**Generational Collection:**
الكائنات الجديدة بتتفحص كثير لأن معظمها بتموت بسرعة. الكائنات القديمة اللي عاشت فترة بتتفحص أقل.

**Incremental Collection:**
بدل التنظيف في مرة واحدة (وده بيعمل تأخير محسوس)، بيتقسم على دفعات صغيرة.

**Idle-time Collection:**
بيشتغل بس لما الـ CPU فاضي، عشان ميأثرش على أداء البرنامج.

---

## 9. الخلاصة

| المفهوم | المعنى |
|---------|--------|
| Garbage Collection | نظام تلقائي بينضف الذاكرة |
| Reachable | كائن تقدر توصله من الـ Roots |
| Unreachable | كائن ملقتش طريق ليه من الـ Roots |
| Roots | المتغيرات العامة + الدوال الشغالة |
| Mark-and-Sweep | الخوارزمية الأساسية للتنظيف |

> **القاعدة الذهبية:** المرجع الداخل هو المهم، مش الخارج.
